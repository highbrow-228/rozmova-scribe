# transcribe

Транскрипція україномовного аудіо з розділенням на спікерів (діаризацією).
Заточено під записи телефонних розмов і нарад: на вході відео або `.wav`,
на виході текст, де кожна репліка підписана `[SPEAKER_00]` / `[SPEAKER_01]`.

Під капотом [whisper-ctranslate2](https://github.com/Softcatala/whisper-ctranslate2)
(розпізнавання, моделі faster-whisper) і [pyannote.audio](https://github.com/pyannote/pyannote-audio)
(діаризація). Рахує на GPU.

## Що потрібно

- `ffmpeg` у системі
- NVIDIA GPU з CUDA — не обов'язкова, але сильно пришвидшує
  (перевірено на RTX 5070 Ti)
- [uv](https://docs.astral.sh/uv/)
- токен Hugging Face з доступом до `pyannote/speaker-diarization-community-1`
  (модель гейтована — треба прийняти умови на її сторінці)

## Налаштування

```bash
uv sync                 # збирає .venv рівно за uv.lock
cp .env.example .env    # далі впиши свій HF_TOKEN
```

Обов'язковий у `.env` лише токен — решта змінних має робочі значення
за замовчуванням і потрібна, тільки якщо хочеш щось змінити.

Усе локальне лежить у самому репозиторії й не комітиться: оточення в `.venv/`,
кеш моделей і пакетів у `cache/`, аудіо та транскрипти в `data/`. Кеш uv
прив'язаний до проєкту через `uv.toml`, тому команди uv треба запускати
з кореня репозиторію.

```
data/
├── wav_need_to_run/   # черга на обробку
├── wav_done/          # оброблені оригінали
└── transcripts/       # результати
```

Самі теки тримаються в git файлами `.gitkeep`, тому після клонування вони вже
на місці — аудіо і транскрипти при цьому не комітяться.

## Параметри транскрипції

Задаються в `.env`, але всі мають значення за замовчуванням — без `.env`
(крім токена) все одно працює:

| змінна           | за замовчуванням | що робить |
|------------------|------------------|-----------|
| `LANGUAGE`       | `uk`             | мова аудіо |
| `SPEAKER_NUM`    | `2`              | скільки спікерів шукати |
| `OUTPUT_FORMAT`  | `txt`            | формат виводу: `txt`, `srt`, `vtt`, `json`, `all` |
| `HOTWORDS`       | порожньо         | слова й терміни через кому, які модель має впізнавати |
| `INITIAL_PROMPT` | порожньо         | опис контексту розмови суцільним текстом |
| `DEVICE`         | автоматично      | `cuda` або `cpu` |
| `COMPUTE_TYPE`   | `float32`        | `float32`, `float16` (лише GPU), `int8` |

Будь-яку з них можна перебити на один запуск — значення з команди має
пріоритет над `.env`:

```bash
SPEAKER_NUM=3 ./run-wav.sh запис.wav
LANGUAGE=en OUTPUT_FORMAT=srt ./run-wav.sh запис.wav
```

Виняток один: порожнім значенням з команди підказки з `.env` не скасувати —
порожнє там означає «не задано». Щоб прогнати запис без підказок, закоментуй
їх у `.env`.

### GPU чи CPU

Скрипти самі перевіряють наявність CUDA-пристрою: є — рахують на `cuda`,
немає — на `cpu`. Налаштовувати нічого не треба, той самий код працює на
обох машинах.

**Якість при цьому однакова.** Тип обчислень скрізь `float32` — єдиний
неквантизований тип, який підтримують і CPU, і GPU, тож транскрипти з обох
виходять побайтово ідентичними.

Варто розуміти, що `float32` обрано заради цієї однаковості, а не заради
точності: ваги моделей на диску збережені у `float16` (2.9 ГБ на 1.55 млрд
параметрів), і `float32` лише розтягує їх у ширший формат, не додаючи
інформації. На трихвилинному дзвінку `float16` і `float32` дали побайтово
той самий текст, а от `int8` розійшовся у двох рядках із 31 — саме він
єдиний реально втрачає якість.

Пристрій задається явно навмисно: за `--device auto` бібліотека відправляє
діаризацію на CPU навіть за наявної відеокарти. На 30-секундному записі це
11.3 с проти 4.0 с.

Орієнтовний час на 30-секундному записі з `large-v3-turbo`: GPU — близько
13 с, CPU — близько 35 с. Більшість часу в обох випадках з'їдає діаризація.
Для довгих записів на CPU має сенс брати `large-v3-turbo`, а не `large-v2`.

Якщо швидкість важливіша за однаковість результату, тип обчислень
перевизначається:

```bash
COMPUTE_TYPE=float16 ./run-wav.sh запис.wav   # лише GPU, швидше
COMPUTE_TYPE=int8 ./run-wav.sh запис.wav      # найшвидше, якість нижча
DEVICE=cpu ./run-wav.sh запис.wav             # примусово на процесорі
```

Статистику по рядках, словах і спікерах скрипт друкує тільки для `txt`
(і для `all`, де `txt` теж є) — за інших форматів просто вкаже теку з
результатом.

## Запуск

**Один файл `.wav`** — головний сценарій. Сам приводить аудіо до 16 кГц моно,
якщо воно в іншому форматі:

```bash
./run-wav.sh запис.wav                    # модель large-v2 за замовчуванням
./run-wav.sh запис.wav large-v3-turbo     # інша модель
./run-wav.sh запис.wav large-v3 vad15     # + мітка, щоб не затерти попередній прогін
```

**Пачка файлів.** Кладеш `.wav` у `data/wav_need_to_run/` і запускаєш. Оброблені
переїжджають у `data/wav_done/`, файли з помилкою лишаються на місці:

```bash
./run-batch.sh                 # усі файли з data/wav_need_to_run/
./run-batch.sh large-v3-turbo  # вказати модель
```

**Відео.** Витягує звук і транскрибує; тимчасовий `.wav` видаляє після себе:

```bash
./run.sh "нарада.mkv"
./run.sh "нарада.mkv" large-v3
```

**Порівняти два прогони** одного запису — скільки рядків і слів у кожному
та побудовний diff:

```bash
./cmp.sh запис.wav large-v2 large-v3
```

Без аргументів `cmp.sh` покаже, які варіанти взагалі є.

Зверни увагу: `cmp.sh` шукає файл `<назва>.txt`, тому з прогонами, де
`run-wav.sh` конвертував аудіо і назвав результат `<назва>_16k.txt`, він не
працює — порівнювати виходить лише те, що подавалося вже в 16 кГц моно.

## Моделі

`large-v2` (за замовчуванням), `large-v3`, `large-v3-turbo`. Turbo помітно
швидший при близькій якості — зручний, щоб швидко прогнати пачку. Ваги
качаються з Hugging Face один раз і лишаються в `cache/hf-cache/`.

## Результати

Кожен прогін кладе теку `data/transcripts/<назва>_<модель>[_мітка]/` з `.txt`
всередині. Наприкінці скрипт друкує, скільки вийшло рядків і слів та як
репліки розподілилися між спікерами.

Якщо `run-wav.sh` конвертував аудіо, файл усередині зветься `<назва>_16k.txt` —
за іменем сконвертованого, а не вихідного.

## Підказки моделі

`HOTWORDS` і `INITIAL_PROMPT` підказують моделі, якої лексики чекати. Обидві
порожні за замовчуванням — тоді whisper запускається без цих прапорців узагалі.
Заповнюються в `.env` під свої записи:

```bash
HOTWORDS="Дія, РНОКПП, IBAN, ФОП, P2P"
INITIAL_PROMPT="Розмова клієнта з оператором банку. Реєстрація в застосунку, картка, рахунок, перекази."
```

Впливають вони помітно: на тому самому дзвінку з банківськими підказками
модель чує «Альянс банку», а без них — «Антезбанком». Тож тримай їх
відповідними до змісту записів, а під різні типи аудіо просто міняй значення
в `.env` (у файлі лежать дві готові заготовки — для дзвінків у банк і для
внутрішніх нарад).

## Інші параметри

Решта налаштувань поки що зашита в `run.sh` і `run-wav.sh`: модель за
замовчуванням (`large-v2`, перебивається другим аргументом) і параметри VAD —
`--vad_threshold`, `--vad_max_speech_duration_s` тощо.
